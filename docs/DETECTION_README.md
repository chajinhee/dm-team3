# 이상 탐지 실험

과제의 강의 알고리즘으로는 **v1 재구성오차 PCA**와 **v1 K-means**를 보고한다. v6는 같은 HAI 23.05 데이터에서 시차 예측 잔차와 추가 정상 학습 자료를 시험한 후속 실험이다.

| 역할 | 실험과 점수 | 강의노트 |
|---|---|---|
| 강의식 PCA | v1 `PCA-0.99`. 정상 센서의 공분산을 고유분해하고, 누적 설명분산 99%를 충족하는 상위 32개 성분에 투영한다. 남은 재구성오차를 센서 차원 수로 나눈다. v6 개발 후보 `PCA-0.99`와 `PCA-0.995`도 이 방식을 사용한다. | `DM_06-Dimension Reduction.pdf` 58–59, 61쪽 |
| 강의식 K-means | v1 `K-means-16`. 정상 표본을 가장 가까운 중심에 할당하고 중심을 평균으로 갱신한다. 가장 가까운 중심까지의 제곱거리가 이상 점수다. | `DM_05-Clustering.pdf` 35–36쪽 |
| v6 시차 잔차 탐지 | 0·1·10초 시차로 현재 표준화 센서 값 및 시차 예측 잔차를 계산한다. 잔차 공분산의 전체 고유쌍으로 정규화된 역공분산을 구하고, 이를 써서 각 센서의 조건부 잔차를 표준화한다. 각 시차에서 절댓값이 큰 세 잔차의 `log1p` 평균을 사용한 뒤, 정상 분위수로 보정한 시차 점수 중 최댓값을 취한다. | 역공분산을 활용하는 마할라노비스형 점수의 변형이며 전 차원을 유지한다. |

쪽 번호는 PDF의 첫 페이지를 1쪽으로 센다. 기존 결과 파일 및 동결 설정과 호환되도록 v6 시차 잔차 모델 키 `PCA-multi`와 출력의 계열 라벨 `PCA`를 유지한다. 그래프에서는 선택된 모델을 **시차 잔차**로 표기한다.

## 실험 설정

| 평가 행 | 사전에 정한 설정 |
|---|---|
| v1 재구성오차 PCA | 누적 설명분산 99%, train1 보정 97.5분위 |
| v1 K-means | k=16, train1 보정 95분위 |
| v6 시차 잔차 | 시차 0·1·10초, 지수 평활 span 10, 확인 1초, 유지 6초, 정상 보정 99.8분위 × 0.95 |
| v6 K-means | k=32, 일반 제곱거리, 지수 평활 span 10, 확인 1초, 유지 6초, 정상 보정 95분위 × 0.90, 최종 seed 331 |

v1은 train1 앞 구간에서 적합하고 뒤에서 보정한 뒤, test1에서 설정을 확정하고 test2로 평가했다. v6 코드에서 개발 명령은 train1과 test1만 읽는다. test1 앞 구간의 1,088개 후보와 뒤 구간의 모델별 배수 7개를 비교한다. 정상 1시간당 오경보 1회와 오탐 60초를 초과한 정도가 가장 작은 설정을 먼저 고르고, 그다음 초 단위 F1과 사건 재현율의 조화평균을 최대화한다. 최종 실행은 train1·2 각 파일 앞 60%로 재적합하고 뒤 40%에서 임계값을 다시 보정한다. train1 단독 잔차 탐지도 대조군으로 실행한다.

## 결과와 평가 범위

| test2 모델 | 정밀도 | 재현율 | F1 | 사건/38 | 오경보/정상h | 오경보 초/정상h |
|---|---:|---:|---:|---:|---:|---:|
| v1 재구성오차 PCA | .779 | .290 | .423 | 13 | .373 | 11.24 |
| v1 K-means | .378 | .305 | .338 | 29 | 29.984 | 68.40 |
| v6 시차 잔차 | .767 | .437 | .557 | 21 | .681 | 18.10 |
| v6 K-means | .096 | .450 | .158 | 28 | 19.671 | 580.29 |

**v1은 test2를 설정 고정 후 평가에 사용한 기준 실험이다. v6의 test2 결과는 후향 비교다.** v6 실행 단계에서 설정을 동결했어도 v2–v6 실험 과정에서 같은 test2를 반복 확인했다. 따라서 F1 .557과 사건 21건은 연구에서 이미 본 데이터에 대한 관측치다. 일반화 성능을 추정하려면 새 공격 레이블을 포함한 독립 평가 자료가 필요하다.

이 후향 비교에서 v6 시차 잔차는 v1 PCA의 13건을 모두 포함해 8건을 더 찾았고, 초 단위 정밀도는 .779에서 .767로 내려갔으며 오경보 시간은 11.24에서 18.10초/h로 늘었다. v6 K-means는 오경보 횟수가 감소했지만 F1은 .338에서 .158로 하락했고 오경보 지속시간은 68.40에서 580.29초/h로 늘었다. v6 시차 잔차의 정상 train4 결과는 .327회/h, 7.29초/h였다. train4는 이미 살펴본 정상 자료이므로 이 수치는 해당 운전 구간의 오경보를 설명한다.

test2의 초 단위 레이블 정렬은 같은 분 안에서 행 순서가 보존됐다는 가정을 따른다.

## 재현 방법

저장소 최상위에서 아래 명령을 실행한다. 다운로드는 고정 커밋의 train1·2·4, test1·2 및 레이블을 받는다. 필요한 원자료는 약 600MB다.

```sh
python -m pip install -r requirements-detection.txt
python -m experiments.run_detection --stage fetch
python -m unittest discover -s tests
python HAI_Project/run.py --data data --out results_before
python -m experiments.run_detection --stage develop
python -m experiments.run_detection --stage final
python -m experiments.make_figures_detection --baseline-summary results_before/summary.json
```

- **v1**은 새로 생성한 `results_before/summary.json`의 `detection`에서 확인한다. 그래프 실행 시 `--baseline-summary`를 생략하면 저장소의 원본 `HAI_Project/results/summary.json`을 사용한다.
- **v6**는 `results/detection/evaluation.csv`에서 검증한다. 선택한 설정과 재적합 후 임계값은 `selection.json`과 `applied_settings.json`에 기록한다. 실제 경보선은 해당 정상 임계값에 모델별 배수를 곱한 값이다. 별도 폴더에서 재실행하려면 개발·최종 평가·그래프에 같은 `--out` 값을 전달한다.
- **비교 그래프**는 v1 요약과 v6 평가 CSV에서 직접 만들어진다. 보고 수치는 저장소에서 실행 가능한 v1·v6에 한정한다. 재실행과 저장된 결과의 대조 범위는 [검증 기록](../results/detection/verification.json)에 있다.
- **공통 모듈**에서 `common.config`와 `common.preprocess`를 사용한다. v6 데이터 어댑터는 파일별 해시와 센서 열 및 초 단위 연속성을 확인해 개발 단계에서 test2를 읽지 않는다. 동결 검사는 코드·설정·프로토콜의 CRLF 줄바꿈을 LF로 통일하고 경로 구분자는 `/`로 기록한다. 텍스트 내용이 바뀌면 개발부터 다시 실행한다. 원자료 해시는 다운로드한 파일의 바이트를 그대로 검사한다.
